# Стенд

Тестовая сеть для разработки. Устройства эмулируются контейнерами, но SSH и команды
у них настоящие, вендорские. Физическое железо не нужно.

Три производителя: коммутаторы Nokia SR Linux, маршрутизаторы FRRouting и
точки доступа OpenWrt. Плюс две рабочие станции Alpine Linux.

## Топология

```
                     core1
       e1/1 /    e1/2 |    e1/3 \    e1/4 \
           /          |          \        \
        acc1 ------- acc2       edge1    edge2
       /  e1/2  e1/2  |  \
  e1/3/  \e1/4        |   \e1/4
    pc1  ap1       e1/3   ap2
                    pc2
```

| Узел  | Адрес         | Что это        | Тип на карте  |
|-------|---------------|----------------|---------------|
| core1 | 172.20.20.11  | Nokia SR Linux | коммутатор    |
| acc1  | 172.20.20.12  | Nokia SR Linux | коммутатор    |
| acc2  | 172.20.20.13  | Nokia SR Linux | коммутатор    |
| edge1 | 172.20.20.21  | FRRouting      | маршрутизатор |
| edge2 | 172.20.20.22  | FRRouting      | маршрутизатор |
| ap1   | 172.20.20.31  | OpenWrt        | точка доступа |
| ap2   | 172.20.20.32  | OpenWrt        | точка доступа |
| pc1   | 172.20.20.101 | Alpine Linux   | не на карте   |
| pc2   | 172.20.20.102 | Alpine Linux   | не на карте   |

Вход на коммутаторы `admin` / `NokiaSrl1!`, на маршрутизаторы `admin` /
`Lab12345!`, на точки доступа `root` / `Lab12345!`.

Рабочие станции на карту не идут: SSH на них не поднят, а продукт ищет
устройства по открытому порту 22.

## Сколько памяти нужно

Узел Nokia SR Linux занимает около полутора гигабайт, и это ограничивает размер
стенда сильнее всего: три коммутатора съедают примерно 4,5 ГБ. Довести парк до
сотни устройств одними коммутаторами Nokia нельзя, это потребовало бы 150 ГБ.

Маршрутизатор FRRouting занимает около 50 МБ, точка доступа OpenWrt около 2 МБ.
Их можно добавлять десятками, не упираясь в память, поэтому парк расширяется
ими, а не коммутаторами.

Образы маршрутизатора и точки доступа собираются на месте, в реестрах их нет:

```shell
docker build -t netmap-frr:latest frr/
docker build -t netmap-openwrt:latest openwrt/
```

## Требования

Linux с ядром 5.x или новее, Docker, containerlab 0.78 или новее, 6 ГБ свободной
памяти. На macOS containerlab не работает, ему нужны сетевые вызовы ядра Linux.

## Установка

```shell
curl -sL https://containerlab.dev/setup | sudo -E bash -s "all"
```

Скрипт ставит Docker и containerlab. Если apt-репозиторий containerlab недоступен,
пакет берётся с GitHub:

```shell
curl -sLO https://github.com/srl-labs/containerlab/releases/latest/download/containerlab_0.78.0_linux_arm64.deb
sudo dpkg -i containerlab_0.78.0_linux_arm64.deb
```

## Запуск

```shell
sudo containerlab deploy -t netmap.clab.yml
```

Остановить и удалить: `sudo containerlab destroy -t netmap.clab.yml`
Посмотреть, что запущено: `sudo containerlab inspect -a`

После перезагрузки хоста контейнеры SR Linux падают по кругу: их сетевое окружение
создаётся при развёртывании и вместе с хостом пропадает. Лечится пересозданием
стенда, то есть destroy и deploy.

**Изменили `startup-config` — пересоздавайте с `--cleanup`.** Обычный `destroy`
оставляет каталог `clab-netmap/`, в нём лежит сохранённая конфигурация каждого
узла. При следующем развёртывании SR Linux загрузится из неё, а containerlab
решит, что конфигурация уже есть, и стартовую не применит. Правка при этом молча
не сработает, хотя команды отработали без ошибок:

```shell
sudo containerlab destroy --cleanup -t netmap.clab.yml
```

## Включить интерфейсы

Интерфейсы на SR Linux по умолчанию выключены, и пока они выключены, LLDP молчит
и соседей не видно. После каждого развёртывания:

```shell
for ip in 172.20.20.11 172.20.20.12 172.20.20.13; do
  printf 'enter candidate
set / interface ethernet-1/1 admin-state enable
set / interface ethernet-1/2 admin-state enable
set / interface ethernet-1/3 admin-state enable
set / interface ethernet-1/4 admin-state enable
commit save
quit
' | sshpass -p 'NokiaSrl1!' ssh -o StrictHostKeyChecking=no admin@$ip
done
```

`commit save` вместо `commit now` пишет правку не только в running, но и в
стартовую конфигурацию. Иначе интерфейсы гаснут при каждом перезапуске
контейнера и поднимать их приходится заново.

Объявление адреса управления в LLDP задаётся стартовой конфигурацией из
`lldp.partial.cfg`, руками его включать не нужно. По этому адресу продукт
привязывает соседа к найденному устройству ещё до входа на него, сам SR Linux
такой TLV не объявляет.

Сам LLDP включать не надо, на SR Linux он работает из коробки. На FRRouting и
OpenWrt lldpd поднимается вместе с узлом.

Свежеразвёрнутый узел SR Linux принимает команды не сразу: пока идёт
применение стартовой конфигурации, ответом будет `commit already in progress`
или `Server timeout`. Достаточно повторить через полминуты.

Проверка:

```shell
sshpass -p 'NokiaSrl1!' ssh admin@172.20.20.11 'show system lldp neighbor'
```

Должно показать acc1 на `ethernet-1/1`, acc2 на `ethernet-1/2`, edge1 на
`ethernet-1/3` и edge2 на `ethernet-1/4`.

## Особенности, которые влияют на код

**LLDP отдаёт соседей и по сети управления.** Все устройства стоят в одной сети
управления и видят там друг друга. Без фильтрации карта превращается в сетку, где
каждый соединён с каждым. Физические линки это `ethernet-*` у Nokia и `eth1` и
дальше у FRRouting и OpenWrt, а `mgmt0` и `eth0` это управление.

**SR Linux не принимает несколько команд через `;`.** Команды подаются потоком
на вход, по одной в строке.

**MAC-адреса коммутаторов назначаются вручную**, из диапазона Nokia `90:EC:E3` по
реестру IEEE. Делается это в `netmap.clab.yml` через `exec`. По умолчанию контейнер
получает адрес Docker с локальным префиксом `02:42`, а по такому адресу
производителя не определить. На живом железе адрес вендорский, так что без этой
правки стенд вёл бы себя не как настоящая сеть.

Маршрутизаторам и точкам доступа адрес не подменяется намеренно. FRRouting и
OpenWrt это программные системы, своего диапазона в реестре IEEE у них нет, а
брать чужой значило бы выдавать одно железо за другое. До входа такое устройство
остаётся без производителя, как и любое с локально назначенным адресом.

**lldpd по умолчанию называет порт MAC-адресом.** Сосед при этом объявляет имя
интерфейса, продукт получает одну и ту же связь с двух сторон разными концами и
рисует её дважды. Лечится строкой `lldpcli configure lldp portidsubtype ifname`,
она стоит в запуске обоих образов.

**OpenWrt задаёт lldpd шаблон интерфейсов из своей сетевой конфигурации**, там
логические имена вроде `lan`. На стенде сетей OpenWrt нет, интерфейсы приходят от
containerlab как `eth1` и дальше, под шаблон не подходит ни один, и демон работает,
не взяв ни одного интерфейса. Лечится строкой
`lldpcli configure system interface pattern "eth*"` в запуске образа.

**Dropbear отдаёт двоичные данные сразу за строкой опознания.** Продукт читает
приветствие SSH при обходе сети, и вместе с ним прилетал обмен ключами с нулевыми
байтами, на которых падал весь обход. Разбирается это в `scanner.py`: берётся
только первая строка, как и требует RFC 4253.

## После приостановки виртуальной машины

Приостановка это не перезагрузка, пересоздавать стенд не нужно. Контейнеры остаются
работать, `sshd` внутри них жив.

Но мост сети управления теряет адрес IPv4, остаётся только link-local IPv6. Хост
оказывается вне `172.20.20.0/24`, поэтому устройства не пингуются и не отвечают
по SSH, хотя `docker ps` показывает их работающими. Возвращается одной командой:

```shell
sudo ip addr add 172.20.20.1/24 dev br-$(sudo docker network inspect netmap-mgmt -f '{{.Id}}' | cut -c1-12)
```

Интерфейсы на устройствах при этом остаются включёнными, заново их поднимать не надо.

Полное пересоздание нужно только после настоящей перезагрузки хоста: тогда пропадает
сетевое окружение контейнеров и SR Linux начинает падать по кругу.

## Если ничего не скачивается

```shell
getent ahostsv4 ghcr.io
```

Адреса вида `0.0.31.x` или `fd00:` означают, что DNS перехватывает прокси на хосте.
Трафик виртуальной машины идёт от процесса `vmnet-natd`, его надо пустить напрямую,
мимо прокси.

## Выводы команд

В папке `samples/` лежат настоящие выводы, снятые с работающего устройства.
Парсеры пишутся по ним, поднимать стенд для этого не нужно.
